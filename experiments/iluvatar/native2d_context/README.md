# 4k 吞吐恢复实验

保留第一版 Native 2D，比较 `prefill`（仅预填充优化）和 `context`（GPU 按真实长度分流）。
首先用 `check_numerics.py` 验证图回放、混合上下文、8192 边界和 FP16/BF16 数值，计时解码内核。
`run_screen.py --gpu 2` 使用同卡两次新一次性容器，与插件关闭的原生基线比较。
4k 使用 4096 输入、1024 输出、64 并发/请求；16k 的 128 输出筛选仅检查预填充收益。
服务使用官网原参数，源文件哈希审计、正确性题、无缓存命中/抢占检查均保留。
通过筛选后仍须用 16k/1024 与官网四轮吞吐、Math500 完整验收。

第一轮 microbench 暴露原生 2D 在 96 序列、dummy 上下文长度 1 的独立 dense 检查差异。
修正版会记录原生 eager 对照，不把此项记为精度通过；真实 4k/16k 仍要求 dense 精度通过。
