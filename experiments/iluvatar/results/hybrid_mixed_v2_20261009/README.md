# 阶段路由原型第二版：混合批次交给 Triton（非计分）

第二版在本地 fork 的实验分支上提交，检查 vLLM 已持有的 `query_start_loc_cpu`，当批次含单 token 解码请求时整批交给 Triton；只有纯预填充批次才交给 FlagGems。检查发生在 CPU 元数据上，不做 GPU→CPU 同步。与先前 [后端 A/B](../attention_ab_20261009/README.md)使用相同 GPU 0、模型、服务参数、测试长度与随机种子，每个版本使用全新个人一次性容器。

| 负载 | 默认 Triton | 第一版路由 | 第二版路由 |
| --- | ---: | ---: | ---: |
| `[16384,1,1,1]` 独立预填充 Total tok/s | 1107.07 | 2465.05 | 2459.19 |
| `[16384,128,8,8]` 混合 Total tok/s | 818.38 | 748.81 | 866.16 |
| 混合组平均 TPOT | 626.17 ms | 799.94 ms | 622.19 ms |
| 混合组平均 TTFT | 79.98 s | 73.02 s | 71.56 s |

第二版在这轮小样本中比默认 Triton 的混合吞吐高约 **5.8%**，同时保留约 **2.22 倍**的单请求预填充优势。混合组 8/8 请求成功，所有组缓存命中与抢占均为 0；监督脚本与容器停止退出码均为 0。这只是一次非计分筛选，不能当作赛题成绩或精度结论。下一步按原版 benchmark 脚本复测 4k、16k 各四轮，且用 Math500 Level 3 验证准确率。

完整客户端、服务、运行与清理日志在本目录；服务器原件位于 `/workspace/wyNomad/results/hybrid_mixed_v2_20261009/`。
