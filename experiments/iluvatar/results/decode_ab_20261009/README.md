# attention 解码负载隔离对照（非计分）

2026-10-09 在天数 BI-V150 物理 GPU 0 上，用未修改的参赛源码及同一套服务参数，顺序测试默认 Triton attention 和 FlagGems attention。两组各在个人一次性容器中运行，先用 `[512,16,1,1]` 预热，再用相同随机种子的 `[512,1024,8,8]` 主测；短输入让主要生成工作发生在解码阶段。

| 主测后端 | 成功请求 | 输出 tok/s | Total tok/s | 平均 TPOT | 中位 ITL | 平均 TTFT |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| Triton | 8/8 | 125.84 | 188.76 | 24.92 ms | 16.66 ms | 39.17 s |
| FlagGems | 8/8 | 114.16 | 171.25 | 33.25 ms | 25.07 ms | 37.31 s |

所有请求成功，前缀缓存命中和抢占增量均为 0。FlagGems 的输出吞吐比 Triton 低约 **9.3%**，平均 TPOT 高约 **33.4%**。这支持保留 Triton 解码路径，但单轮小负载仍不足以预测赛题正式 16k／1024、64 并发成绩。TTFT 包含服务首次请求阶段的编译开销，不用于判断解码内核速度。

两组 probe 均退出 0，分别生成 `finished.ok`。最后一次 `docker stop` 在 45 秒处超时，导致监督脚本 `runner.exit=1` 且未生成总 `finished.ok`；随后通过 `docker ps -a` 和 `docker inspect` 确认个人容器已经删除。此超时发生在测量结束后的清理阶段，不改变已保存的基准日志。服务器原件位于 `/workspace/wyNomad/results/decode_ab_20261009/`，本地校验清单见 `../SHA256SUMS.txt`。
