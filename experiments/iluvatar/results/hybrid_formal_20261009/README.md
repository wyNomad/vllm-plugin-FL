# 修复版混合注意力：16k 正确性与正式吞吐

`run_after_accuracy.py` 是个人目录的串行门控脚本。只有修复版 Math500 的 105 题精度检查通过且个人容器已经释放，才分别启动默认 Triton 与修复版混合后端的约 16k token 确定性问答。两组均需返回合理答案、输入长度超过 16k token，并清理各自一次性容器，随后运行 `run_and_cleanup.py`。

正式吞吐使用原仓库 `benchmarks/benchmark_throughput_serve.py`，固定服务参数与基线一致，测试 `[4096,1024,64,256]`、`[16384,1024,64,128]` 两组，各四轮，舍弃首轮。首次启动于 2026-10-09 23:27，发现长输入客户端的 token 计数错误后保留 `pipeline_invalid_prompt.log`，修复脚本并重新启动。两组 16,379 token 对照都给出正确答案。原版 benchmark 于 **23:53** 实际开始，随后完成八轮；`raw_runs_20261009_235354.csv`、`summary_20261009_235354.csv`、完整运行日志和自动清理证据均已同步本地。服务器原件仍在 `/workspace/wyNomad/results/hybrid_formal_20261009/`。

| 场景 | 默认 Triton 基线 Total tok/s | 修复版混合后端 Total tok/s | 变化 | 平均 TTFT 基线→候选 | 平均 TPOT 基线→候选 |
| --- | ---: | ---: | ---: | ---: | ---: |
| `[4096,1024,64,256]` | 1977.17 | 1880.12 | **-4.91%** | 11616.10→12207.56 ms | 148.55→156.64 ms |
| `[16384,1024,64,128]` | 918.04 | 866.21 | **-5.65%** | 598124.12→632150.91 ms | 486.02→516.63 ms |

`benchmark_results/` 中八轮原始记录均为 `SUCCESS`，成功请求数与每轮总请求数相等；两组汇总均可由各自后三轮复算。`runner.exit=0`、`benchmark_succeeded.ok`、`pipeline_succeeded.ok`，`container_stop.log` 记录 `docker stop` 返回码 0，服务器上个人容器已删除。修复版 Math500 精度 **0.9714** 虽达到 0.95 门槛，但这版在两个正式负载都稳定慢于基线，**不能作为性能优化提交候选**。先前未经 KV 写入修复的小负载提速不适用于正式结果。下一步需分别量化独立 KV 写入和混合路由元数据开销，再决定新方案；当前实验开关默认关闭，原版 Triton 路径仍是默认后端。
